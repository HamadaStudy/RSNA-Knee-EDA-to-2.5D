# `rsna-knee-baseline-v1.ipynb` 解説

参照実装（pilkwang_kim, RSNA Knee Abnormality Detection）の読解メモ。
対象ファイル: `rsna-knee-baseline-v1.ipynb`（35セル）

構成は「§1 評価指標 → §2 ラベル → §3 撮像の読み取り → §3b スライス順序 → §4 サンプリング →
§5 左右正規化 → §5b キャッシュ → §6 集約ヘッド → §6b 学習済み重みの読み込み → §7 検証」で、
各章の散文が直後のコードの設計根拠になっている。以下、セル番号は 0-indexed。

---

## 全体像

このノートブックの核心は **「1 study = 数百枚の DICOM」を「6枚の3チャンネル画像（= 6スロット）」に
圧縮し、スロット単位の attention で12診断に落とす** という設計。

```
train_series/{Study}/{Series}/*.dcm            ← 1 study ≈ 5〜8 series × 数十 slice ≈ 150ファイル
        │
        │ ① walk()+probe(): series ごとに「中央の1枚」だけヘッダ読み（16スレッド）
        ▼
  series テーブル（SeriesDescription, TR, TE, PixelSpacing, ImagePositionPatient …）
        │
        │ ② annotate(): fatsat / weight(T1,T2,PD,GRE) / fluid / px を復元
        ▼
        │ ③ pick_slots(): (plane × fluid × fatsat) の6述語で series を1本ずつ選抜
        ▼              → 1 study あたり最大6 series（残りは捨てる）
        │ ④ order_slices(): 選ばれた series の全 slice のヘッダを読み k = p·(r_x×r_y) でソート
        ▼
        │ ⑤ read_slot(): 順序付き stack の中央帯 20〜80% から 3 slice だけ decode
        │              → 130mm 物理クロップ → 336px リサイズ → 1〜99%ile 正規化 → uint8
        ▼
        │ ⑥ normalise_laterality(): 右膝を左膝規約へ（cor/ax は左右反転、sag は slice順反転）
        ▼
  cache: uint8 [n_study, 6, 3, 336, 336]  +  mask: float [n_study, 6]   ← メモリ常駐
        │
        │ ⑦ Model.forward(): (B,6,3,H,W) → (B*6,3,H,W) → DINOv2 → slot 特徴 (B,6,768)
        ▼
        │ ⑧ SlotHead: 診断ごとのクエリで6スロットに masked attention
        ▼
  logits (B, 12) → sigmoid → 列ごとに rank(pct) → submission.csv
```

## 1. 「1 study → 12確率」の作り方

1 study には複数 series があり、各 series に数十枚の dcm がある。この階層をどう畳むかが本実装の中心。

### ステップ1: series → 6スロットへの選抜（セル16 `pick_slots`）

「撮像面 × 流体強調 × 脂肪抑制」の直積で **6つのスロット**を定義（セル13 `SLOTS_RECOVERED`）:

| slot | plane | weighting | fat sat | 主に何が見えるか |
|---|---|---|---|---|
| `SAG_FLUID_FS` | Sagittal | PD/T2 | yes | 半月板断裂・骨髄浮腫・関節液 |
| `COR_FLUID_FS` | Coronal | PD/T2 | yes | 側副靭帯・半月板体部 |
| `AX_FLUID_FS` | Axial | PD/T2 | yes | 膝蓋大腿関節・滑膜 |
| `SAG_FLUID_NOFS` | Sagittal | PD/T2 | no | 高CNRでの半月板形態 |
| `COR_T1` | Coronal | T1 | no | 骨梁・骨輪郭 |
| `SAG_T1` | Sagittal | T1 | no | 解剖・慢性変化 |

膝を3面で読むのは構造の走行方向が違うため（十字靭帯は斜走＝サジタル、側副靭帯と半月板体部＝コロナル、
膝蓋軟骨と支帯＝アキシャル）。12所見それぞれに「よく写る系列」が最低1つ対応するようスロットが選ばれている。

各スロットに該当する series が複数あれば **`n_slices` が最大のもの1本**だけを採用（厚いスタック＝関節を
密にサンプルしている＝3スライスサンプラーに余裕が出る）。**該当がなければそのスロットは空のまま**で、
代替は入れない。コメントに理由が明記されている:

> T1スロットを脂肪抑制なし PD/T2 で埋めると、4407 study のうち 2383 で同一 series が2スロットを占め、
> T1スロットの56%が非T1になる。presence mask が「撮っていない系列を撮った」と主張し、§6の
> per-diagnosis softmax が同じ内容の2スロットに注意を分割して、片方の撮像に約2倍の重みを与えてしまう。

**結果: 数百 dcm → 最大6 series。** 使われない series（PCL専用の斜位、localizer、重複echo など）は
完全に捨てられる。

### ステップ2: series → 3スライス（2.5Dの正体、セル19 `read_slot`）

- **slice の並び順を幾何から復元**（§3b）。ファイル名は SOP Instance UID なので名前順ソートは解剖学的
  順序と無相関（実測 Spearman ρ ≈ 0.009）。`ImageOrientationPatient` の面内軸2本の外積で法線 n を作り、
  `k = ImagePositionPatient · n` で単調な through-plane 座標を得てソート。取れなければ `InstanceNumber`、
  それも無ければ元の順序（ログにカウントだけ残す）。
  - ここを間違えると「2.5Dの3チャンネルが無関係な3断面になる」「スタック中央が単なるランダム部分集合に
    なる」「左右正規化のための順序反転が何も反転しない」の3つが同時に、エラーなしで壊れる。
- 順序付きスタックの **20%〜80% の帯**（`SLICE_BAND`）から `np.linspace` で **3枚**を等間隔サンプル。
  端のスライスは関節外の軟部組織が主なので捨てる。
- その **3枚を RGB の3チャンネルに積む**（`GROUP = 3`）。これが「2.5D」＝ 3D畳み込みを使わずに隣接
  スライスの文脈を2Dエンコーダに与える手法。
- 物理スケール正規化（§4）: `PixelSpacing` からピクセル数 `want = CROP_MM / px` を計算して中心クロップ
  してから `out_size` にリサイズ。輝度は **サンプルしたスタック全体の 1〜99 パーセンタイル**で正規化
  （スライスごとではなく series ごと。スライス間の相対コントラストを保つため。極値でなくパーセンタイル
  なのは1本の明るい血管に全体を圧縮させないため）。
- 最後に `uint8` に落とす。読み取りスレッドとエンコーダの間でキューに滞留するバッファなので、float32 の
  1/4 で済ませる。輝度はすでに [0,1] に正規化済みなので8bitの損失は双線形リサイズが既に払ったコストの範囲。

**結果: 1 study で実際に decode される dcm は 6スロット × 3スライス = 最大18枚だけ。**
約150ファイルの study が18ファイルに落ちる。ただし順序復元パスでは選抜 series の**全 slice のヘッダ**を
1回読むので、ここが I/O のボトルネック（専用の32スレッドプール `ORDER_THREADS` と 5400秒の
`ORDER_BUDGET_S` シーリングが付いている）。

`N_GROUP_MAX = 1` なので現状キャッシュは3スライス固定。この定数を上げると1スロットに複数「グループ」を
持てて、学習時はランダムに1グループ（スタック方向の augmentation になる）、推論時は全グループ平均という
設計に拡張される（セル31 `predict`、セル30 `predict_member` の TTA）。

### ステップ3: スロット埋め込み → 12ロジット（セル25 `SlotHead`、セル26 `Model`）

```
imgs (B, 6, 3, H, W) ──reshape──> (B*6, 3, H, W)   # エンコーダは study 構造を見ない
   /255 → 必要なら img_size へ双線形リサイズ → ImageNet 正規化
   DINOv2 → last_hidden_state (B*6, 1+N_patch, 384)
   parts = [ CLS,  patch トークンの平均 ]  → concat → 768次元
   reshape → feat (B, 6, 768)                      # ヘッドはピクセルを見ない
```

診断ごとの attention:

```
h_s     = GELU(Linear(LayerNorm(x_s))) + slot_emb[s]        # h: (B, 6, 256)
α[o,s]  = softmax_s( <h_s, q_o> / √256 )   ただし mask=0 のスロットは -1e4 で除外
c_o     = Σ_s α[o,s] · h_s                                  # (B, 12, 256)
ℓ_o     = <c_o, w_o> + b_o                                  # (B, 12)
```

ポイント:

1. **`mask` による softmax の再正規化**が「1 study に紐づく series 数がバラバラ」問題への回答。
   軸位断がない study では、その診断の attention が存在するスロットに再配分されるだけで、
   ゼロベクトルを食わされない。
2. 最後の出力層は普通の `nn.Linear` ではなく `(ctx * out.weight.unsqueeze(0)).sum(-1) + out.bias`。
   **診断 o の context を、その診断専用の重み行 w_o だけで読む**（12個の独立した内積）。
3. ヘッドが意図的に小さい理由が§6に書かれている。ラベルは study 単位なので「study のどの部分に所見が
   あるか」を教える教師信号が存在せず、スロットより下の粒度に attention を置いても学ぶ材料がない
   （supervision が粗いならヘッドも粗くする）。
4. 学習済みメンバーを読み込む場合のみ、`SLOT_PRIOR_TABLE`（例: `ACL: (0,3,5)` = サジタル系スロット）で
   attention ロジットに固定バイアス +0.55 を足す経路がある（exp(0.55)≈1.73倍）。学習パラメータではなく
   buffer なので state_dict と一緒に運ばれる「そのメンバーの定義の一部」。

### ステップ4: 確率 → 提出（セル33 `write_submission`）

sigmoid 出力を **列ごとに `rank(pct=True)`** に変換してから書き出す。§1 の「AUC は単調変換不変」を根拠に、
キャリブレーションは捨てて順位だけ残す。`test.csv` に left join して欠損は 0.5 埋め。アンサンブルも
確率平均ではなく **rank 平均**（`submission_rankmean.csv`）。

## 2. 使用しているモデル

| 要素 | 内容 |
|---|---|
| エンコーダ | **DINOv2 (ViT-S/14 既定)**。`transformers.AutoModel.from_pretrained` で `/kaggle/input` 配下からマウント先を探索（`find_dinov2`） |
| 特徴プーリング | `cls_mean` = CLS + パッチ平均 の連結（384×2=768）。オプションで `cls_mean_focal` = さらに各チャンネルのパッチ方向 top-1/8 平均を連結（所見が視野の一部しか占めない問題への対処） |
| 凍結方針 | 全パラメータを freeze してから **最後の6ブロック**＋最終 LayerNorm のみ trainable（`UNFREEZE_LAST=6`） |
| ヘッド | `SlotHead`（hidden 256, dropout 0.2） |
| 最適化 | AdamW, **backbone lr 8e-6 / head lr 1e-3**（100倍差）, weight_decay 0.02, OneCycleLR (pct_start 0.15), AMP + GradScaler |
| 学習 | 10 epoch, batch = **8 study**（= 48 スロット画像）, 損失は **重み付き BCEWithLogits** |
| 解像度実験 | `RUNS = [224px, 336px]` を同一キャッシュから比較 |

### 解像度の決め方（§4）

130mm クロップなので実効ピッチは `CROP_MM / P`: 224px → 0.580 mm/px、336px → 0.387 mm/px。
幅 d mm の構造がリサンプルを生き残るには Nyquist から `s_eff ≤ d/2` が必要で、半月板断裂は 1〜3mm。
つまり d=1mm には 0.5mm/px 以下が要るので **224 は原理的に不足、336 は充足**。
「これはリサイズの性質であってネットワークの性質ではない（第1層の畳み込みに届く前に信号が破壊される）」
という主張が明示されている。

クロップ幅 130mm の根拠も測定値: 学習 series 全体で取得FOV（Rows × PixelSpacing）の中央値は 160mm、
範囲 70〜320mm。160mm クロップは 60% の series で画像より大きく（＝クロップが黙って行われず物理スケールが
未正規化のまま通過する）、130mm は 99.6% の series の FOV を下回りつつ関節を含む。

### エンコーダを凍結しない理由（§6直後の散文）

自己教師あり特徴は自然画像由来で「PD 画像上の半月板断裂の signal」に相当する語彙を持たないため、
解像度・エンコーダサイズ・スライス数・スロット集約をいくら改善しても凍結エンコーダの天井に当たる。
ただし初期ブロックは汎用エッジ／テクスチャ検出器で、このデータ量では改善する見込みが薄く破壊する見込みは
十分あるので後段だけ開ける。学習率を head と 100倍差にするのも同じ理由（head は乱数初期化で全部学ぶ必要が
あり、encoder は良い解から少し動かすだけでよい。単一 lr では head が学習不足か encoder が数百ステップで
壊れるかのどちらかになる）。

### augmentation は意図的に薄い（セル31 `augment`）

回転±8°, ズームイン方向のみ+8%, 平行移動±5%, 輝度±10%。**左右反転も上下反転も使わない**:

- 左右反転は §5 の左右正規化を毎バッチ台無しにする（ヘッダパスを走らせて確立したものを1バッチごとに壊す）。
- 上下反転は「ラベルが変わらない方向」ではなく分布外に出す操作。膝は canonical な向きで撮像され、
  このコーパスに自分の上下鏡像に見える study は存在しない。
- そもそも所見がフレーム内のどこにあるかは情報であってノイズではない（Baker 嚢胞は「膝窩にあること」で
  同定される）。
- ズームアウトを禁じているのも `padding_mode="border"` が端の行を外側に複製し、まさに膝窩部の組織を
  捏造してしまうため。

## 3. ラベルの付け方

`train.csv` は大半の行で12ラベルが null、`Report`（多言語の読影レポート）だけがある。
**`test.csv` に `Report` 列がない**ので、テキストは推論時の入力に使えず、教師信号の生成元にしか使えない
（テキストブランチを持つ fusion モデルは推論時に読むものがないので排除される）。

### 3-a. レポート → 12スコアの抽出器（セル6〜11）

英・西・仏・蘭・独・土・クロアチア/セルビア・希・ブルガリアの **9言語を同時に**扱うルールベース抽出器。
言語判定はしない（判定を先にやると証拠を読む前に賭けることになる。`'la '` のような安い判定は西・仏で
衝突して先に走った方が両方飲み込む）。

1. **正規化** (`normalize`): トルコ語の ı/İ を先に畳んでから casefold、NFKD で分音記号を除去
   （ギリシャ語レポートの多くが μ に MICRO SIGN U+00B5 を使っている問題も NFKD が吸収）
2. **節分割** (`clauses`): 句読点と改行で分割し、**`Fractures :` のような見出し行を次行に連結**
   （`Aucune.` と切り離すと否定が陽性に化ける）。連結された見出しは単独では残さない。長い節は
   カンマでさらに分割（列挙の中に別の主張が隠れる）
3. **極性判定** (`_polarity`): `UNCERTAIN` → hedge、`NEGATION` → 陰性、`NORMALITY`
   （"dentro de límites normales" 等）→ 陰性扱い（ただし同じ節に `TEAR` や `grade 3/4` があれば陽性）。
   否定はエッジケースではなく、いくつかの所見では言及の大半が否定（レポートは「調べて正常だったもの」を
   列挙するため）
4. **所見マッチ**: 3種類の構造
   - **PAIRED**（ACL/MCL/内側・外側半月板）: 解剖語 × 病理語（`TEAR`/`DEGEN`/`INJURY`）の同時出現が必要。
     フレーズ辞書が外れたら **語幹＋左右修飾語の文字距離55字以内**でフォールバック（トルコ語の接尾辞、
     クロアチア語・ギリシャ語の格変化に対応。文字窓なのは語順が言語で違うため——英語は側性形容詞が名詞の前、
     ギリシャ語・ブルガリア語は後ろ）。さらに `_wrong_side` で「対側の修飾語のほうが近い」節を除外
     （PCL の記述1つが「ACL は正常」を上書きする事故を防ぐ。*presence* ではなく *どちらが近いか* で
     判定するのは "posterior horn" が膝レポートの定型句だから）
   - **OA**（内側/外側/PF）: `OA_EVIDENCE`（骨棘・軟骨欠損・chondropathy・関節裂隙狭小化…
     "osteoarthritis" とはまず書かれない）× コンパートメント指定
   - **DIRECT**（Effusion/Synovitis/Baker's/Contusion/Fracture）: 語自体が所見。`DECOY` で
     `microfracture`（手術手技）や `meniscal cyst` を除外。なお `no fracture` は意図的に decoy に
     入れていない（decoy は節をスキップするので、英語で最頻の否定表現が「沈黙」に化けてしまう）
5. **段階付け** (`_severity`): `SEV_HIGH` → 1.0 / `SEV_LOW` → 0.45 / 無修飾 → 0.75。
   **二値化しない**のが重要。§2 の理由: 読影医と annotator は閾値を共有していない
   （"small joint effusion" が陰性アノテーションと併存しうる）ので「語がある ⇒ 陽性」は構成的に誤り。
   AUC は順序しか読まないので段階付けはタダ
6. **スコア化** (`_score_clauses`):
   - 陽性あり → `min(0.95, 0.50 + 0.42·best + 0.03·min(n_pos,3))`、conf = `min(1.0, 0.55+0.15·n_pos)`
   - 陰性のみ → `max(0.04, 0.20-0.04·n_neg)`、conf = `min(0.9, 0.45+0.12·n_neg)`
   - **言及なし → score 0.28, conf 0.05**（＝「沈黙は明示的陰性より上」）
7. **横断補正**: `tricompartmental OA` / `gonarthrose` のような関節全体の記述は3つの OA ターゲット全部の
   証拠にする（個別評価がない場合のみ）。Synovitis は画像に写るがテキストに書かれないことが多いので、
   沈黙時は Effusion スコアの一部を継承（`0.28 + 0.45*(Effusion - 0.28)`）

### 3-b. 二重のラベル源（セル14 `read_labels`）

- `/kaggle/input` に `report_labels*.csv`（LLM がレポートを読んだ表）がマウントされていればそれを優先。
  **カバーされない study だけ**辞書式にフォールバック（run 単位ではなく study 単位の縮退）
- 表がマウントされていないなら辞書式のみ（fork した読者のための通常経路）
- ただし「label を名前に含むディレクトリがマウントされているのに使える表が見つからない」場合は
  `LabelSourceError` で **run を殺す**。理由がコメントに明記されている: 弱いラベルで学習した run は
  正常終了して妥当な submission を書き、違いはログ1行にしか出ない。例外を握り潰す `try/except` の
  対象外にしている2つのエラーのうちの1つ（もう1つは重み不一致の `WeightsError`）
- 辞書 vs LLM の判定は**アノテーション一致率ではなく「沈黙率」**で行うという議論が§2にある。
  アノテーション付き study は数十件しかなく、Hanley–McNeil の標準誤差が ±0.17 程度になって2つの辞書を
  区別できない。一方「(レポート, 所見) ペアで何かマッチしたか」は正解不要で全 study に計算でき、
  言語別に集計すれば語彙の穴の場所を指せる（辞書の失敗モードは誤りではなく沈黙であり、沈黙は
  二値抽出器では自信のある陰性と区別できない → 「ギリシャ語話者は所見が少ない」ように見えるコーパスになる）

### 3-c. 学習ターゲットとサンプル重み（セル33 `main`）

```python
if st in gold.index:          # train.csv に12ラベルが揃っている study
    Y[i], W[i] = gold.loc[st].values, 3.0          # 画像から読まれた唯一のラベル → 3倍重み
elif st in lab.index:         # レポート由来
    Y[i] = r[TARGETS].values                        # 0.04〜0.95 の連続値をそのまま BCE の目標に
    W[i] = 0.25 + 0.75 * r[conf].values             # 所見ごとの信頼度が重みになる
```

損失は `BCEWithLogits(reduction="none") * W` の平均。つまり **ラベルごとに重みが違う**
（レポートが synovitis について何も言っていない study は、その出力を弱くしか引っ張らない）。

## 4. 左右の正規化（§5, セル21）

12ターゲットのうち4つ（内外側半月板、内外側大腿脛骨コンパートメント）は medial/lateral の対で、
5つ目（MCL）は自分がある側で命名されている。medial/lateral は体の正中に対して定義されるので、
それが *画像の* どちら側に来るかは「どちらの膝を撮ったか」で決まる。正規化しないとこの5ラベルは
モデルが観測できない軸から学習することになる。

補正は面によって違う:
- **コロナル/アキシャル**: medial-lateral 方向が画像面内にあるので最終軸を反転（`torch.flip(dims=[-1])`）
- **サジタル**: 各スライス自体は鏡像化で変わらず、違うのは「スタックが関節を横断する順序」なので
  **スライス順を反転**（`torch.flip(dims=[0])`）

`Laterality` (0020,0060) は Type 2C で正当に欠損しうる。**このコーパスでは半数の study で欠損**し、
しかもベンダー単位でまとまって欠ける。欠損を放置すると「全部左膝」扱いになり、その中の右膝が全部
鏡像で入る。患者座標系（LPS: +x = 患者の左）から復元する:

```
c = p + r·Δ_c·(N_c/2) + d·Δ_r·(N_r/2)          side = R if c_x < 0 else L
```

`ImagePositionPatient` そのもの（＝画像の**隅**）ではなく**画像中心**を使うのが要点で、両者は最大で
FOV の半分ずれ、正中付近の膝では符号が変わる。study 内の series の中央値を閾値処理し、正中±20mm
(`LAT_MIN_OFFSET_MM`) 以内は判定放棄（タグ付き半分と照合して全体97%正解、20mm 以内は偶然と同等）。

なお `side_from_corner_x` / `RULES_LEGACY` は「過去に学習されたメンバーが使っていた誤ったルール」を
**修正せず再現**するためのもの（修正するとそのメンバーの重みが見たことのない画素を渡されることになる）。

## 5. キャッシュ設計（§5b, セル23 `build_cache`）

コストは演算ではなく読み取りに支配される。1 study は約150ファイルで、1回なら払えるが epoch ごとには
払えない（fine-tuning は毎 epoch 同じ画素を要求する）。よってスロット画像を一度だけ decode して
`uint8` でメモリ常駐:

```
bytes = N_study × N_slot × S × P²
```

**解像度が二乗で効き、スライス数は線形**。つまりカバレッジが安い軸で解像度が高い軸。予算が効いたときに
譲るのはスライス数（`plan_cache`）。予算は `/proc/meminfo` の `MemAvailable` の 45%（上限24GB）で、
**学習用とテスト用の両方が同時に常駐する**ため両者の合計で見積もる（見えるテスト分割はスタブなので
`TEST_SHARE = 0.30` を下限に置く。学習コーパスだけで見積もると「観察できる run は全部通り、点数が付く
run だけが溢れる」）。

順序復元は独立したパスとして先に走る。選抜 series の全スライス分のヘッダを開くので、その後の decode より
はるかに多いファイルオープンになり、ネットワークマウント上では作業量ではなくレイテンシ支配 → 専用の
広いスレッドプール。`RSNA_ORDER_CACHE` 環境変数を設定すると順序を JSON に記憶できる
（順序は DICOM 幾何だけの関数で、解像度にもスライス数にも依存しないため）。ファイル数が変わっていれば
再計算する検証付き。

## 6. 検証設計（§7）

- **リーク源1: 共有レポート。** 正常膝のテンプレート読影で **レポートがバイト単位一致する study 群**が
  存在し、同一の派生ターゲットベクトルを共有する。だから `md5(Report) % 5` で分割し、重複群を割らない。
  `grp == 0` の1/5を holdout、固定（ローテーションしない）
- **リーク源2: 2つの基準の混同。**
  - *holdout*（派生ターゲットとの一致、n が十分）が epoch 選択と設定選択を担う
  - *annotation check*（放射線医の画像読影との一致＝コンペが測るもの）は **holdout に落ちた
    アノテーション付き study だけ**で計算し、報告するが決定には使わせない
  - アノテーション付き study は3倍重みで学習に残している（画像から読まれた唯一のラベルで、捨てるには
    少なすぎる）。だからこそ評価は holdout 内に限る必要がある——それ以外で評価すると、最も重く学習した
    正解済みサンプルでの暗記を能力として報告することになる

## 7. 「学習しない」経路（§6b, セル30）

`main()` は最初に `find_weights()` を見て、`manifest.json` を持つ重みパッケージがマウントされていれば
**学習を一切せず推論のみ**（`infer_from_package`）。ノートブックはデータセットを attach できて、
重みはデータセットである——事前にできない部分は「誰も見ていない study を読んで予測すること」だけ、という論法。

- メンバーは `pixel_group`（`img`/`group`/`slices`/`crop_mm`/`band`/`rules`/`slots` の JSON）で
  グルーピングされ、**グループごとに1回だけ decode**
- `RULES` として「形状に一切現れないが画素を変える4つの決定」——slice の順序規則、左右判定規則、
  スロットのフォールバック可否、decode 失敗時の埋め方——を native/legacy の2値で持ち回る。異なる読み方で
  decode されたメンバーは**エラーも出さずに正常動作し、間違った画像から妥当な submission を書く**ため
- **fingerprint**（セル30）: 各メンバーは「シード固定の合成入力に対する自分の出力」を持ち歩き、使用前に
  再計算して 2e-3 の許容差で照合。GPU 間の数値差は約1e-5、前処理の食い違いは order 1 で出るので、
  許容差はその間に置かれている。不一致なら `WeightsError` で停止
- 残り時間に応じて **TTA窓を先に削り、メンバーは最後まで残す**（窓は他の窓と重複する視点1つ、メンバーは
  独立した1票）。時間見積りは「固定費（チェックポイント読み込み＋モデル構築＋fingerprint）」と
  「窓あたり費用」を別々に計測する（合計を窓数で割ると固定費が変動費として価格付けされ、削減が見積りを
  膨らませる暴走になる）
- 最初に必ず `write_benchmark_submission()`（全部0.5）を書く。OOM の SIGKILL は `try/except` に届かない
  ので、有効なファイルが1秒目から存在する状態にしておき、本物の予測ができたときだけ上書きする

## 8. 評価指標から逆算された設計（§1）

スコアは12ラベルの ROC AUC の非加重平均。ここから3つの設計判断が確定する:

1. **順序だけが読まれる。** AUC は各ラベルのスコアの任意の単調増加変換に対して不変なので、
   キャリブレーションと閾値は無価値。アンサンブルの結合方法も決まる——生確率の平均は「最も自信のある
   モデル」が支配するが、**rank の平均**は指標が読む唯一の情報を結合する
2. **全ラベルが等コスト。** 良いモデルの平均 AUC を M とすると、1ラベルを偶然（0.5）に放置すると
   他の11がどれだけ良くても `(M-0.5)/12` を失う（M=0.85 で 0.029）。**稀な所見ほど注意を払う価値が高い**
   （稀な所見が最も簡単に偶然レベルに落ちるため）
3. **有病率のドリフトは生き残れるが閾値は生き残れない。** AUC は期待値として陽性率に不変で、コンペも
   train/public/final で有病率が一致する保証はないと明記している。唯一残る閾値は「holdout AUC を
   計算するために段階付きターゲットを中点で二値化する」箇所だけで、これは epoch と設定の選択にしか
   使われず、提出スコアには一切関与しない

## このリポジトリに移植するときの注意点

1. **`Fluid_Sensitive` と `Fat_Suppression` は独立していない。** §3 に「学習 series の全行で両者が
   一致する＝実質1軸しか持たない」とある。だから TR/TE/`SeriesDescription`/`ScanOptions` から
   ヘッダ再推定している（TR ≲ 800ms → T1、TR ≳ 800 かつ TE ≳ 60 → T2、TR ≳ 800 かつ TE ≲ 60 → PD、
   ただし GRE は TR が設計上短いので `ScanningSequence` で先に判定）。
   `SLOT_SCHEME=public` にすると提供フラグだけを使う対照実験になる（この場合 `SAG_STRUCT` スロットに
   T1 と非脂肪抑制 PD/T2 が混ざり、組織コントラストが大きく異なるものが同居する）
2. **`Laterality` タグはこのコーパスの半数の study で欠損**（ベンダー単位）。§4 の通り患者座標系から
   復元しないと、側性依存の5ターゲットが右膝で軸反転して学習される
3. **学習側のデータは全件ある**（4407 study / 24371 series / dcm 中央値 162枚per study）が、
   **`test_series/` は 3 study だけ**（コンペ側のスタブ。採点対象は非公開）。したがって
   `infer_from_package` 経路のテスト側キャッシュ見積りやテスト推論の時間計測はローカルでは無意味。
   一方 `pick_slots` の充填率（`train slots per study: mean/min/max`）や `lat_of` のタグ／幾何の
   内訳は全件で再現できるので、EDA としてはここが安い第一歩
4. **`ORDER_CACHE`（環境変数 `RSNA_ORDER_CACHE`）はローカルでこそ有効。** slice 順序は解像度にも
   スライス数にも依存しないので、設定を変えて何度も回すローカル環境では順序パス（最大の I/O コスト）を
   1回で済ませられる。Kaggle 上では毎 run 新しいマシンなので既定で無効
5. **`find_root()` は `data` ディレクトリも探索する**（`data/test.csv` と `data/test_series/` があれば
   採用）。このリポジトリは `data/raw_dataset/` 配下なので、そのまま動かすには `ROOT` の与え方を変える
   必要がある
